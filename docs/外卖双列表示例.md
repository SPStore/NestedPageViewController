# 外卖点餐双列表示例

在 `Example/NestedPageExample.xcworkspace` 中运行 `NestedPageExample` 或 `FoodOrderingDemo` scheme，默认均显示示例首页，再从「高级示例」分组进入「外卖点餐双列表」。UI 测试自行传入 `-food-demo` 参数直达该页，不影响日常 Run。

这是基于组件公开 API 的交互实验。核心提供通用的头部展开及进度控制能力，双列表、轮播与联动动画仍放在 Demo 业务层。它不代表美团内部的实现。

滚动协调已提炼到 Demo 的 `BusinessComponents/DualScroll`，不随基础库发布。接入说明见 [双列表业务组件](../Example/NestedPageExample/BusinessComponents/DualScroll/README.md)。

## 交互

- 第一页为分类 / 商品双列，另有评价、商家两个分页。
- 店铺封面采用暖色渐变品牌背景、装饰图案和独立信息卡，展示店名、评分、配送与优惠信息；全部本地绘制。
- Tab 使用项目已接入的第三方 `JXCategoryView`，整体居左，评价右侧以小字展示示例评价数 `1710`。
- Tab 下方是高度 144 的共享横向活动区，包含 6 张卡片，自由滚动、不分页；右侧商品区域仍是 3 页独立分页轮播。素材使用本地文字和 SF Symbols，无网络请求和自动轮播计时器。
- Tab 吸顶后显示「点餐 ↑」；点击该项会进入点餐页，用约 0.32 秒的 ease-out 动画同步展开封面和共享轮播，左右两列仍保留各自的阅读位置，不受位置保留开关影响。箭头隐藏时点击只切页，横滑切页也不会触发展开。右侧独立轮播不强制恢复，仍跟随右侧内容位置。动画中拖动或切页会从当前位置接管；系统启用「减弱动态效果」时立即展开。
- 左右上滑均先收起店铺头部；Tab 吸顶后继续收起公共轮播，跨过第二个边界的剩余位移才交给被操作的列表。
- 公共轮播收完后左右独立滚动：拖分类不会卷走右侧小轮播；右侧小轮播与商品一起纵向滚动。
- 左侧分类和右侧商品列表均关闭顶部 / 底部回弹；两个轮播的横向滚动保持不变。
- 两处轮播内起拖均优先于外层横向分页，包括边缘和斜拖；横拖只滚轮播，纵拖由商品列表承接。轮播以外的横向翻页与点击 Tab 保持可用。
- 左点右滚并跳过两个轮播，右滚更新分类选中项。
- 商品分组标题吸在公共 tab 下；最后一个分组提供 8 个商品，减少底部补足留白，仍可通过分类跳转到顶部。
- 「短分类 / 长分类」切换 4 / 16 个分类；「重置」返回点餐页、更新布局并将分类移到当前可见区域顶部，商品位置仍按保留配置处理。
- 商品的 + 按钮只更新本地购物车计数，不会产生订单。

本示例的 `keepsContentScrollPosition` 在进入页面时读取 `NestedPageConfig.shared`，对应设置页的「保持内容滚动位置」。修改开关后重新进入示例生效；默认关闭，应用重启后恢复默认值。`headerBounces = false` 等其他示例配置保持固定，不套用其余全局配置。

注意：位置保留开关作用于核心组件的主列表，左侧分类由业务组件 `NestedPageDualScrollCoordinator` 协调。现有「重置」通过 `updateLayouts()` 更新布局：开启位置保留时保留商品阅读位置，关闭时商品列表恢复初始位置。

位置保留开启后，允许“店铺展开但右侧仍在原商品位置”的悬空状态。此时左栏下拉的静止边界取当前可见区域顶部，不预留已经滚走的公共轮播，也不会把右侧商品拉回顶部或产生回弹。

下拉规则：分类先回到自身顶部；右侧独立内容（包含小轮播）也在顶部时，继续下拉分类先恢复公共轮播，再展开店铺。右侧独立内容尚在深处时，分类停在当前可见区域顶部，不带动商品回到顶部。右侧自身回到顶部后，也按公共轮播、店铺的顺序恢复。

## 实现要点

页面容器顶部延伸到屏幕顶端，让 380 点高的店铺封面铺在透明系统导航栏下方；导航栏不显示标题，背景随封面收起逐渐显现。封面文案位于导航栏下方 24 点，信息卡底部留出 28 点。列表左右仍由 `safeAreaLayoutGuide` 约束；购物车内容区固定 58 点且位于底部安全区之上，暖色背景铺满屏幕底部与两侧安全区，文字仍避开安全区，分页容器延伸到购物车顶部。双列表的吸顶底边包含导航栏实际高度和 Tab 高度；轮播裁剪、分类定位共用该边界，不重复叠加设备安全距离。

顶部渐变由页面内独立背景层绘制：横向铺满根视图，从屏幕顶端覆盖到系统导航栏的实际底边，并随布局变化更新。系统导航栏各状态始终透明，避免折叠屏外屏的顶部留白露出封面，也避免两层半透明背景叠加。背景层不接收触摸，不影响系统按钮或滚动手势。

商品 collectionView 的 frame 全宽，商品 cell 和 sectionHeader 在左侧预留分类栏宽度，因而组件挂载的共享头部仍然全宽。

商品列表的第 0 个 section 是全宽轮播的等高占位，第 1 个 section 是右侧轮播，后面才是商品分组。真实共享轮播由业务容器的独立裁剪层展示，仍挂在商品列表内部以复用原生纵向手势；它不依赖第 0 个 cell 是否可见，因此商品在深处时也能重新展开。布局和分类跳转显式区分这两个前导 section，不让轮播参与商品分类高亮或分组吸顶。

分类容器与商品列表是兄弟视图。容器从“Tab 实际底边 + 公共轮播剩余可见高度”开始裁剪；内部分类 tableView 的 frame 进行反向补偿，使其在点餐页中的原点始终为 0，高度始终为全页高度。这样折叠公共区域不会改变正在拖拽 / 减速的列表的 viewport 尺寸。

分类 offset 包含共享区域折叠量和分类自身滚动量。共享区域的最大折叠量为店铺高度 200 + 公共轮播高度 144；Tab 高度 44 不参与折叠。右侧驱动时，只向分类同步共享区域的位移；左侧驱动时，这部分位移已经包含在原生 offset 中，不再重复同步。分类内容不足时用 bottom inset 补足整个共享区域所需的滚动范围。

共享区域收完后，右侧轮播才开始随右侧独立内容滚走。它在公共区域收起期间仍会随整体上移，“独立”不代表这时固定在屏幕上。

每个轮播另外挂载一个不限制方向的 pan，只用于排除外层分页，不驱动任何滚动，也不阻止轮播横拖、商品纵拖、点击或系统返回。外层分页等待这个 pan 失败，而不是等待可能因纵向 / 斜向起手而失败的轮播 pan；整次拖动即使移出轮播区域，也不会中途切换 Tab。未改动系统 scrollView pan 的 delegate，也不临时开关分页手势。

第三方 Tab 通过 `contentScrollView` 关联分页容器。箭头按 Tab 的实际底边判断吸顶：非吸顶时首项只计算「点餐」文字宽度，吸顶后才加入箭头及间距，并动态重排后续项；指示器始终对齐「点餐」文字中心。只更新首项宽度模型、Tab 布局和指示器，不调用会重定位分页的整体刷新，保留横滑中的分页进度。点击前记录箭头状态，JX 完成切页后调用 `menu.expandSharedHeader(animated: true)`，无需重复切页，也不调用 `scrollToTop()` 或重置分类。

展开由两层配合：核心 `expandHeader()` 立即恢复封面，`setHeaderExpansionProgress(_:)` 支持 0（吸顶）至 1（完全展开）的进度，均补偿各页 offset 以保留相对 Tab 的阅读位置；业务协调器使用一个显示时钟同步调整封面与共享轮播，每一帧从原阅读锚点计算两列绝对偏移，避免像素舍入误差逐帧累积。保存的是可见区域内的阅读位置，不是要求 `contentOffset` 数值不变。再次上滑时先收封面、再收共享轮播，之后才滚动所操作的列表。每一帧的补偿完成后再更新分类高亮，避免中间 offset 误触发分类联动。

代码入口：

- `FoodOrderingViewController.swift`：整页、共享头部、分页、购物车和重置入口。
- `FoodOrderingTabStrip.swift`：第三方 Tab 的评价数小字、吸顶箭头与无障碍标签。
- `FoodShopCoverView.swift`：本地渐变店铺封面与信息卡。
- `FoodMenuViewController.swift`：接入业务协调器，提供分类 / 商品数据、分类跳转、高亮和商品分组布局。
- `BusinessComponents/DualScroll/NestedPageDualScrollCoordinator.swift`：共享位移分配、边界、短内容补足及运动状态。
- `BusinessComponents/DualScroll/NestedPageDualScrollView.swift`：双列表布局和副列表裁剪。
- `BusinessComponents/DualScroll/NestedPagePagingGestureGuard.swift`：横向内容优先于外层分页。
- `FoodCarouselView.swift`：两处轮播、横纵拖拽方向判断与本地卡片。
- `FoodOrderingTests.swift`：真实 UIKit 视图与组件 KVO 链路的回归测试。
- `NestedPageDualScrollCoordinatorTests.swift`：脱离外卖页面的业务组件复用、代理所有权及释放测试。
- `FoodCarouselUITests.swift`：模拟器实际手势、横向轮播、纵向联动及切页测试。

## 验证

在 Xcode 选择 `FoodOrderingDemo`，执行 Test。单元测试保留无轮播版本的回归场景，并验证两个共享边界的位移分配、顶部越界位移防护、两列独立滚动、短分类、末尾商品组定位、切页及尺寸变化。它通过模拟 dragging / decelerating 状态测试真实 UIKit 布局和组件 KVO 链路。

UI 测试另外发送实际拖拽事件，检查两处轮播的首尾边缘、横向 / 纵向占优斜拖不误切页，轮播上的纵拖可滚页面，公共轮播只露出一部分时仍可横滑且系统边缘返回可用，以及左栏收起公共轮播但保留右侧轮播、切页 / 更新布局保留商品位置、在评价页展开头部后返回点餐下拉左栏不留空白。多指并发、真机快速甩动手感仍需继续手动验收：

1. 从左右两边分别缓慢上推、快速上甩，观察跨越 Tab 吸顶、公共轮播收完两个边界是否连续。
2. 分类滚到中间后向下拖，确认先回分类顶部，再恢复公共轮播、展开店铺。
3. 商品滚到深处时拖分类，确认商品位置保持；点分类后确认商品分组对齐 tab 下边。
4. 左侧仍在减速时点击评价，再返回点餐，检查分类裁剪位置和商品顶部是否出现空隙。
5. 对短分类重复上述操作，再旋转设备、点击重置。
6. 在两处轮播上分别横拖、纵拖、斜拖，确认横拖不误切 Tab，纵拖继续带动页面；公共轮播只露出一部分时也重复检查。
7. 在设置页开启「保持内容滚动位置」后重新进入示例，右侧滚到约 3 号餐，切换评价并下拉展开店铺，再返回点餐下拉左栏。松手后分类应贴在 Tab 下，右侧仍保留原商品位置。
8. 吸顶后分别在点餐页、评价页点击「点餐 ↑」，确认封面与公共轮播展开，分类和商品仍保留原来的阅读位置；开关两种状态都要验证。再次滑动左右列表应先收共享区，分类跳转仍对齐 Tab 下方。横滑返回点餐仍按位置保留配置处理。
