# 外卖点餐双列表示例

在 `Example/NestedPageExample.xcworkspace` 中运行 `NestedPageExample`，从基础示例进入「外卖点餐双列表」。也可以直接运行 `FoodOrderingDemo` scheme。

这是基于现有公开 API 的交互实验，未改动组件 Sources。它不代表美团内部的实现。

## 交互

- 第一页为分类 / 商品双列，另有评价、商家两个分页。
- 左右都能上滑收起店铺头部；跨过吸顶边界的剩余位移交给被操作的列表。
- 吸顶后左右独立滚动；左点右滚，右滚更新分类选中项。
- 商品分组标题吸在公共 tab 下；最后一个分组只有一个商品，也可通过分类跳转到顶部。
- 「短分类 / 长分类」切换 4 / 16 个分类；「重置」展开头部并回到点餐页顶部。
- 商品的 + 按钮只更新本地购物车计数，不会产生订单。

本示例固定 `headerBounces = false`、`keepsContentScrollPosition = false`，不套用设置页的全局配置。

下拉规则：分类先回到自身顶部；商品也在顶部时，继续下拉分类可以展开店铺。商品尚在深处时，分类只在 tab 下回弹，不带动商品回到顶部。右侧自身回到顶部后，可以继续下拉展开店铺。

## 实现要点

商品 collectionView 的 frame 全宽，商品 cell 和 sectionHeader 在左侧预留分类栏宽度，因而组件挂载的共享头部仍然全宽。

分类容器与商品列表是兄弟视图。容器从公共 tab 的实际底边开始裁剪；内部分类 tableView 的 frame 进行反向补偿，使其在点餐页中的原点始终为 0，高度始终为全页高度。这样折叠头部不会改变正在拖拽 / 减速的列表的 viewport 尺寸。

分类 offset 包含两部分：共享头部折叠量和分类自身滚动量。右侧驱动时，只向分类同步头部的位移；左侧驱动时，这部分位移已经包含在原生 offset 中，不再重复同步。分类内容不足时用 bottom inset 补足收起头部所需的范围。

代码入口：

- `FoodOrderingViewController.swift`：整页、共享头部、分页、购物车和重置入口。
- `FoodMenuViewController.swift`：两列协调、分类跳转和商品分组布局。
- `FoodOrderingTests.swift`：真实 UIKit 视图与组件 KVO 链路的回归测试。

## 验证

在 Xcode 选择 `FoodOrderingDemo`，执行 Test。测试模拟 dragging / decelerating 状态，覆盖跨吸顶边界的位移分配、顶部回弹、两列独立滚动、短分类、末尾短商品组、切页及尺寸变化。

这些测试不覆盖原生手势识别、真实惯性速度曲线和多指并发，需要在模拟器或真机继续手动验收：

1. 从左右两边分别缓慢上推、快速上甩，观察跨吸顶边界是否连续。
2. 分类滚到中间后向下拖，确认先回分类顶部，再展开店铺。
3. 商品滚到深处时拖分类，确认商品位置保持；点分类后确认商品分组对齐 tab 下边。
4. 左侧仍在减速时点击评价，再返回点餐，检查分类裁剪位置和商品顶部是否出现空隙。
5. 对短分类重复上述操作，再旋转设备、点击重置。
